# 設計レビュー議事録 #001 — 将軍×CODEX 設計レビュー機構そのもの

> **テーマ**: 将軍が CODEX (Codex CLI) を設計フェーズで安全に呼ぶ機構の MVP 設計
> **記録形式**: [design_review_template.md](./design_review_template.md) に準拠

---

## 1. 論点

「将軍が設計フェーズで CODEX を呼ぶ機構」を MVP として整備するにあたり、
最小構成・責任系統・記録様式をどう設計すべきか。
過剰設計（専用エージェント化／自動ルーティング／スコアリング／多段レビュー会議）
は本当に不要か。

## 2. 前提

- multi-agent-shogun は将軍・家老・奉行・軍師・足軽の階層型マルチエージェント基盤。
- CODEX (Codex CLI) は `mcp__codex__codex` 経由で MCP ツールとして利用可能。
- 既に殿が CODEX (gpt-5.4) に本機構そのものをレビューさせた実機実績がある
  （その結果が本議事録の素材）。
- 本リポジトリには `docs/design/` 配下に cmd_177 の別件設計書 2 件が存在するが、
  本レビューのスコープ外。

## 3. 非目標

- CODEX を「自動レビュー」「自動採否」「自動実装計画化」に発展させること。
- CODEX の出力を将軍判断と同格に扱う仕組みを作ること。
- レビュー会話の生ログ全文保存。
- 専用エージェント化／自動ルーティング／スコアリング／多段レビュー会議。

## 6. sessionId

殿が実機実行したセッションを単発で消費。新規発行・再現用に保存していない。
今後の再審時は**新規セッションで切り直す**ことを `design-review-codex` スキルに明記済み。

## 7. 継続 or リセット理由

**リセット（新規セッション）方針**を採用。理由:

- 「将軍×CODEX 機構そのものの設計」というテーマ単体で完結するため、他テーマ
  との混在は文脈汚染リスクが高い。
- CODEX 自身の指摘 #2「sessionId 継続は文脈汚染と再現性低下」を採用した結果。

## 8. CODEX の主要批判

CODEX (gpt-5.4) からの 8 指摘 + MVP 推奨形 + 総括を、4 区分に整理:

| # | 種別 | 要約 |
|---|------|------|
| 1 | 批判点 | 将軍直接呼び出しは速いが**責任系統が曖昧化**する。CODEX 発言が決定根拠化しやすい |
| 2 | 失敗条件 | sessionId 継続は文脈汚染・再現性低下を招き、議事録に対象設計案の版・参照リポ状態・sessionId・継続/リセット理由を残さねば監査不能 |
| 3 | 批判点 | レビュー専任を厳密化しすぎると「危ない／弱い」で終わる。穴の指摘＋失敗条件の明示＋最小対案までは許容、ただし最終案選定・実装計画分解・組織命令は禁ずべき |
| 4 | 失敗条件 | 議事録を「会話ログ保存」と捉えると形骸化。残すべきは論点／前提／非目標／設計案の版／主要批判／採否／未解決リスク／再審条件。「何が変わったか」1 行で書けない記録は価値が薄い |
| 5 | 失敗条件 | 入力バイアスに弱い。依頼テンプレに制約／捨てた代替案／運用上の懸念／既知の嫌な点を**強制入力させない**と確認バイアス増幅器になる |
| 6 | 批判点 | 人間との会話中に毎回呼ぶ運用は即興のもっともらしい反論を量産しやすい。**軽量な赤旗チェック**と**文書を読ませる本レビュー**は分離せよ。リアルタイム壁打ちは重大懸念 3 件抽出に限定、設計判断は別ターンの記録へ |
| 7 | 最小対案 | MVP は少なくてよい。**固定プロンプト／レビュー依頼テンプレ／read-only／docs/design 議事録テンプレ**の 4 点で十分。専用エージェント化・自動ルーティング・スコアリング・多段レビュー会議は過剰設計 |
| 8 | 未解決論点 | 見落としがちな重大リスクは**政治利用**。設計品質向上でなく説得材料や責任回避に使われ始めると壊れる。議事録に CODEX 意見と将軍判断を分離、不採用の批判も残す運用に |
| 推奨 | 最小対案 | 将軍直属の外部レビュアとして位置付け、1 設計案 = 1 セッション、出力は批判点＋失敗条件＋最小対案＋未解決論点だけ。議事録は要約された判断記録 |
| 総括 | 批判点 | 本案の本当の弱点は技術でなく**権威・文脈・記録の設計**。ここを曖昧にすると便利でもすぐ腐る |

## 9. 採否（採用・不採用を理由付きで）

### 採用したもの

| # | 採用した指摘 | なぜ採用したか |
|---|--------------|----------------|
| 1 | CODEX を外部監査人に固定、議事録に最終決定者と採否理由を将軍側の言葉で明記 | 責任系統の曖昧化は基盤の腐食を招く。スキル本体（D001/D002）と議事録テンプレ項目 10「最終決定者」で強制 |
| 2 | 1 設計テーマ = 1 セッション、版・参照リポ状態・sessionId・継続/リセット理由を記録 | 再現性と監査可能性は MVP でも捨てられぬ。テンプレ項目 4〜7 で強制 |
| 3 | 出力を批判点＋失敗条件＋最小対案＋未解決論点に限定（最終案選定・実装計画分解・組織命令を禁止） | 役割越境を起きる前に塞ぐのが安い。スキル「固定プロンプト」に一字一句反映 |
| 4 | 議事録は判断記録に整形（全文ベタ貼り禁止）、「何が変わったか」1 行を必須 | 形骸化防止コストは低く、価値が高い。テンプレ項目 13 で強制 |
| 5 | 依頼テンプレ 5 項目（設計案／制約／捨てた代替案／既知の嫌な点／非目標）の強制入力 | 確認バイアス増幅は MVP こそ起こりやすい。スキル「レビュー依頼テンプレ」で強制 |
| 6 | 軽量な赤旗チェックと本レビューを分離、リアルタイム壁打ちで設計判断を確定させない | リアルタイム反論の即興採択は実害が大きい。スキル禁止事項 D006 で明文化 |
| 7 | MVP 4 点セット（固定プロンプト／依頼テンプレ／read-only／議事録テンプレ）で開始 | CODEX 自身の推奨と本タスクの要求が一致。多段化・自動化は実運用で必要が見えてから |
| 8 | 政治利用を防ぐため、CODEX 意見と将軍判断を分離、不採用の批判も残す | 議事録の信頼性は組織運用の信頼性そのもの。テンプレ項目 9「採否」で採用／不採用を両方残す構造に |

### 見送ったもの（過剰設計）

| # | 見送った指摘・提案 | なぜ見送ったか |
|---|---------------------|----------------|
| A | 専用エージェント化（CODEX 専用 pane／専用役職の新設） | CODEX は MCP ツール経由で十分。役職追加は階層複雑化のコストが MVP では割に合わない（CODEX 指摘 #7 と一致） |
| B | 自動ルーティング（タスク種別から自動でレビュー呼出） | 呼ぶか否かの判断こそ将軍の責任。自動化は責任系統の再曖昧化リスク（指摘 #1 と矛盾） |
| C | スコアリング（CODEX 指摘に重み付けして合否判定） | 数値化は監査人の意見を「決定根拠」に格上げする副作用が大きい（指摘 #1 と矛盾） |
| D | 多段レビュー会議（複数 LLM の合議） | 即興反論の量産・責任の更なる曖昧化リスク（指摘 #6 と矛盾）。実運用で具体課題が出てから検討 |
| E | 会話ログ全文の自動保存 | 議事録形骸化の主因（指摘 #4）。判断記録に整形して残す方針を優先 |

## 10. 最終決定者

**将軍**（殿の承認のもと）

CODEX の指摘は採否の素材でしかなく、決定根拠ではない。
本機構の採用・運用は将軍の責任で実施し、殿に最終承認を得る。

## 11. 未解決リスク

- **政治利用リスク（CODEX 指摘 #8）**: 議事録分離方針で予防はしているが、実際に
  「説得材料」「責任回避」用途で使われ始めた兆候を検知する仕組みは未整備。
- **赤旗チェックと本レビューの境界**: 「軽量チェック」と「本レビュー」の使い分け
  運用ルールはスキルに明記済だが、実運用で曖昧になる懸念が残る。
- **議事録ファイル数の増加**: docs/design/ 配下が長期的に肥大化した際の整理運用
  （アーカイブ・索引）は未設計。

## 12. 再審条件

以下のいずれかが発生した場合、本機構そのものを再レビューに掛ける:

1. 議事録が **3 ヶ月で 0 件**、または **1 ヶ月で 10 件以上** のいずれかになった
   （前者は形骸化、後者は呼びすぎの兆候）。
2. CODEX 指摘を「採用率 100%」または「採用率 0%」で運用した議事録が連続発生した
   （前者は決定根拠化、後者は形だけの監査の兆候）。
3. CODEX の API 仕様・モデル名（`gpt-5.4` 系）に破壊的変更が入った。
4. 政治利用の兆候（説得目的の引用・責任回避目的の議事録）が観測された。
5. 専用エージェント化／自動化を本気で検討せざるを得ない具体的な運用課題が
   3 件以上同時に挙がった。

## 13. このレビューで何が変わったか（1 行）

**将軍が CODEX を外部監査人として安全に呼べる作法（固定プロンプト・依頼テンプレ・read-only・1 テーマ 1 セッション）と判断記録様式（議事録テンプレ 13 項目）が確立し、過剰設計（専用エージェント化・自動ルーティング・スコアリング・多段会議）は当面見送ると決まった。**
