## CODEX の指摘（採否は将軍・殿が判断）

### 採用（設計を変える）

### 保留・要検討（未解決論点）

- **真実源が未定**: tmux表示/git/ファイル実体/エージェント応答/Task のどれを優先するか → v0.2 で優先順位表を定める
- **「復旧成功」の定義がない**: 送信成功/応答再開/進捗再開/成果回収 のどこで復旧完了とするか → 定義必須
- **詰まり語（空回り/宙吊り/凍結）が観測可能な形でない**: 人間の直感語のまま。自律判定に耐えるよう観測可能な基準に落とす
- **殿への報告遅延の許容幅**: どの不確実性・停滞なら重大分岐でなくても上げるか → 閾値を決める

## CODEX 最小対案の核（v0.2 の背骨にする）

> 自律ループを「復旧主体」でなく **「異常の封じ込め主体」** に縮める。
> 勝手に前進させるより先に「これ以上広げない」を優先する。
> 全ペイン常時監督でなく、**怪しいものだけ厳しく見る**設計が tmux 基盤に合う。

## 将軍の所見

CODEX の指摘は「安心こそ危険」（[[yonkajou-anshin-koso-kiken]]）を構造的に裏付けた。
v0.1 は「自律化＝将軍が代わりに全部やる」だったが、これは殿の負担を将軍に移すだけで、
将軍が新たな単一障害点になる。正しい方向は **「自律化＝暴走の封じ込めと、怪しい箇所の
厳格確認に絞る」**。全部を自動で前進させるのでなく、止めるべきを止め、上げるべきを上げる。

→ **v0.2 で「封じ込め主体」へ再設計**する（将軍フェイルセーフ・UI操作の危険寄り扱い・
2系統一致の完了判定・dashboard不確実性露出・監視縮退・巡回世代管理）。
