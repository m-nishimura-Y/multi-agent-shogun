## v0.3 の最重要分岐：現行統治との整合（D6・未解決の核）

CODEX が CLAUDE.md:361 / linear-operation-guide:147 を実際に読んで指摘：
- **dashboard は家老責任・将軍は読む側**（CLAUDE.md）
- **Linear が正本・dashboard は高速サマリ**
- **ポーリング禁止**（API節約）

v0.2 は「将軍が dashboard 更新」「将軍が定期巡回」を前提にしており、**この3つと正面衝突**する。
→ v0.3 は「自律将軍が現行統治を**上書きするのか従うのか**」を先に決めねばならない。
これは設計でなく**統治の意思決定**ゆえ、殿の裁可事項。

## CODEX 最小対案の核（v0.3 の背骨）

1. 異常対応ループと**異常発見ループを分離**。発見は印非依存の安価な劣化検知だけ残す
2. **実装完了 と 要求達成 を分離**。後者は別起源の確認を要する
3. heartbeat/健康判定を**将軍自身から切り離す**
4. 世代番号を「**副作用を打つ権利**」に使う
5. UI解除は回数でなく**適用条件**で縛る
6. dashboard は正本に寄せず、**既存正本（Linear）への参照付きサマリ**に留める

## 将軍の所見

第1撃（v0.1）は「将軍が単一障害点」を突いた。第2撃（v0.2）は**もっと深く**、「封じ込めに寄せたら発見を失った」「実装と要求達成の混同」「そもそも現行統治と喧嘩している」を突いた。特に D6 は、将軍が設計に没頭して**既存の掟（ポーリング禁止・dashboard家老責任・Linear正本）を忘れていた**——四か条「二」の継ぎ目そのもの。CODEX が既存ファイルを読んで気づかせた。

→ v0.3 は「統治との整合（殿裁可）」を先に固めてから設計に入る。設計だけ先行すると二重権威化する。
