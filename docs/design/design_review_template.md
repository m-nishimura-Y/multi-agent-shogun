# 設計レビュー議事録テンプレート

> `design-review-codex` スキルで CODEX に設計レビューを依頼した際、
> その結果を**判断記録**として残すためのテンプレート。
>
> **保存対象は判断記録であって、会話ログ全文ではない**。
> 「このレビューで何が変わったか」を 1 行で書けない議事録は価値が薄い。

---

## 使い方

1. 本ファイルを `docs/design/design_review_NNN_<topic>.md` としてコピー
   （NNN は 3 桁連番、topic はスネークケース短名）
2. 下の 13 項目を全て埋める。空欄禁止（該当なしの場合は「該当なし」と明記）
3. push は殿判断。コミットまでで止めること

---

## 議事録

### 1. 論点
（このレビューで決めたかったことを 1〜3 行で。「○○を採用してよいか」「○○の弱点は何か」など）

### 2. 前提
（議論の出発点となる条件・既存の決定事項。後から「そんな前提あったか」とならぬよう明文化）

### 3. 非目標
（このレビューでは扱わないこと。CODEX の過剰指摘・スコープ越境を抑える）

### 4. 対象設計案の版
（レビューに掛けた設計案の版番号・ファイルパス・コミットハッシュ等。再現性のため必須）

### 5. 参照したリポ状態
（CODEX に見せたリポ・ブランチ・コミット・対象ディレクトリ。`read-only` で何を読ませたか）

### 6. sessionId
（CODEX セッションの sessionId。新規発行なら新規発行と明記）

### 7. 継続 or リセット理由
（前セッションを継続したか、新規セッションを切ったか、その理由。原則は 1 テーマ 1 セッション）

### 8. CODEX の主要批判
（CODEX 出力の「批判点 / 失敗条件 / 最小対案 / 未解決論点」を要約。生ログは貼らない）

| # | 種別 | 要約 |
|---|------|------|
| 1 | 批判点 |  |
| 2 | 失敗条件 |  |
| 3 | 最小対案 |  |
| 4 | 未解決論点 |  |

### 9. 採否（採用・不採用を理由付きで）

**採用したもの**

| # | 採用した指摘 | なぜ採用したか |
|---|--------------|----------------|
|   |              |                |

**見送ったもの**

| # | 見送った指摘 | なぜ見送ったか（過剰設計／優先度低／非目標 等） |
|---|--------------|---------------------------------------------|
|   |              |                                              |

### 10. 最終決定者
（**「将軍」または「殿」の名で明記**。「CODEX が言った」は決定根拠にしない）

### 11. 未解決リスク
（採用後も残るリスク。次の議論・実装に持ち越す課題）

### 12. 再審条件
（何が起きたら／何を確認したら再レビューに掛けるか。例：「実装後 1 ヶ月で運用事故が出たら」「該当機能の規模が N 倍になったら」）

### 13. このレビューで何が変わったか（1 行）
（**1 行で書けないなら論点設定を見直せ**。例：「○○を採用し、××は当面見送ると決まった」）
