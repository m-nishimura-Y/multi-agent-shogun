# タスク割当マニュアル

## 基本原則

- **各足軽に専用ファイル**で指示を出す
- **1足軽 = 1タスク**（完了まで）
- **同一ファイル書き込み禁止**（競合防止）

---

## ファイル構成

```
queue/tasks/
├── ashigaru1.yaml  ← 足軽1専用
├── ashigaru2.yaml  ← 足軽2専用
├── ashigaru3.yaml  ← 足軽3専用
└── ashigaru4.yaml  ← 足軽4専用
```

> **注意**: 足軽5-8（別働隊）は軍師の管轄。奉行は関与しない。

---

## タスクファイルの書き方

```yaml
task:
  task_id: subtask_001
  parent_cmd: cmd_XXX
  priority: medium  # critical / high / medium / low
  description: |
    【タスク名】

    ## 背景
    なぜこのタスクが必要か

    ## 実装内容
    具体的な作業内容

    ## 対象ファイル
    /path/to/target/file

    ## 完了条件
    - 条件1
    - 条件2

  recommended_skills:
    - skill-name  # 用途

  reference_docs:  # プロジェクト固有ドキュメント（あれば）
    - ~/projects/xxx/docs/yyy.md

  target_path: "queue/reports/ashigaru1_report.yaml"
  status: assigned
  timestamp: "YYYY-MM-DDTHH:MM:SS"

report_to: "multiagent:0.X"  # 奉行のpane番号
```

## 推奨スキルの記載（必須）

**タスク割当時に推奨スキルを記載せよ。** 足軽がスキルを探す手間を省く。

### 記載方法

1. **逆引き表を参照**: [docs/guides/skill-reverse-lookup.md](../../docs/guides/skill-reverse-lookup.md)
2. **タスク種別から推奨スキルを特定**
3. **タスクファイルに `recommended_skills:` を追加**

### 例

```yaml
# NestJS API追加タスク
recommended_skills:
  - api-endpoint-scaffold      # Controller+Service+DTOをセット生成
  - nestjs-route-order-checker # 静的/動的ルート順序問題を検出

# React画面作成タスク
recommended_skills:
  - react-mui-crud-scaffold    # API Schemaから一覧・詳細・フォーム生成
  - react-code-review-checklist # 実装後の品質レビュー
```

### 推奨スキルがない場合

単純な修正タスク（1ファイルの数行修正）はスキル不要。
`recommended_skills: []` と明示するか、フィールド自体を省略可。

## 参照ドキュメントの記載

**プロジェクト固有のドキュメントがある場合、タスク指示書に `reference_docs:` を追加せよ。**

### プロジェクトドキュメントの場所

```
~/projects/{プロジェクト名}/docs/
```

例:
- `~/projects/document-ai/docs/` - OCR API仕様
- `~/projects/s-automation/docs/` - S-automation設計書

### 記載方法

```yaml
task:
  description: "押印確定API実装"
  recommended_skills:
    - api-endpoint-scaffold
  reference_docs:
    - ~/projects/document-ai/docs/README.md        # OCR API仕様
    - ~/projects/s-automation/docs/design/xxx.md   # 関連設計書
```

### いつ記載するか

- **外部API連携**: 連携先のAPI仕様書
- **既存機能の修正**: 関連する設計書
- **複雑な仕様**: 仕様書・決定事項ドキュメント

足軽が「何を読めばいいか」迷わないようにせよ。

## 同一ファイル書き込み禁止（RACE-001）

```
❌ 禁止:
  足軽1 → output.md
  足軽2 → output.md  ← 競合

✅ 正しい:
  足軽1 → output_1.md
  足軽2 → output_2.md
```

---

## タスク割当の流れ

1. 家老からタスクを受領
2. タスクを本隊4名に分解
3. 各足軽用のYAMLを作成
4. notify.sh で起こす
5. **停止して報告を待つ**（待機ループ禁止）
6. 足軽が send-keys で起こしてくる
7. 報告を確認
8. 家老に集約報告

---

## 「起こされたら全確認」方式

Claude Codeは「待機」できない。

```
❌ やってはいけない
足軽を起こした後、「報告を待つ」と言う

✅ 正しい動作
1. 足軽を起こす
2. 「ここで停止する」と言って処理終了
3. 足軽がsend-keysで起こしてくる
4. 全報告ファイルをスキャン
5. 状況把握してから次アクション
```
