# 知見管理マニュアル

## 役割分担

| 役割 | 責務 |
|------|------|
| **家老** | 知見候補の**集約**（本隊・別働隊の両方から） |
| **奉行** | 知見候補の**精査・評価・Obsidian登録** |

---

## フロー

```
家老から依頼 → 奉行（精査）→ 奉行（評価）→ 奉行（登録）→ 家老に報告
```

---

## 精査基準

### 登録すべき知見

| 基準 | 説明 |
|------|------|
| 再利用性 | 他のタスクでも役立つ |
| 発見困難性 | 「知ってれば一瞬、知らなきゃハマる」系 |
| 具体性 | 解決策が明確 |

### 却下すべき知見

| 基準 | 説明 |
|------|------|
| 既存重複 | Obsidianに既に同様の知見がある |
| 一般的すぎる | ドキュメントを読めば分かる |
| プロジェクト固有 | 他で使えない |

---

## Obsidian登録手順

### 1. 重複チェック

```
Obsidian MCPで検索:
mcp__obsidian__obsidian_global_search
query: "知見のキーワード"
```

### 2. カテゴリ決定

| カテゴリ | 対象 |
|----------|------|
| fe | フロントエンド（React, MUI, TypeScript等） |
| be | バックエンド（NestJS, Prisma, API等） |
| general | 汎用（設計パターン, Git, 開発環境等） |

### 3. ノート作成

```
mcp__obsidian__obsidian_update_note
targetType: filePath
targetIdentifier: "developer/knowledge/{category}/{title}.md"
content: |
  ---
  category: {category}
  discovered_by: {足軽名}
  discovered_at: {日時}
  tags: [knowledge, {category}]
  ---

  # {title}

  ## 問題
  {何が起きたか}

  ## 解決策
  {どう解決したか}

  ## 参考
  {関連リンク等}
```

### 4. knowledge.yaml 更新

```yaml
# queue/shared/knowledge.yaml
- id: K-XXX
  status: registered  # pending → registered
  registered_at: "2026-03-06T12:00:00"
  obsidian_path: "developer/knowledge/fe/xxx.md"
```

## 家老への報告

登録完了後、家老に報告：

```bash
~/multi-agent-shogun/bin/notify.sh multiagent:0.0 '奉行より報告。知見3件をObsidianに登録完了。詳細は queue/shared/knowledge.yaml を確認されよ。'
```

---

## 却下の場合

```yaml
# queue/shared/knowledge.yaml
- id: K-XXX
  status: rejected
  rejected_reason: "既存知見 K-042 と重複"
```

## チェックリスト（登録前）

- [ ] Obsidianで重複チェックしたか？
- [ ] カテゴリは適切か？
- [ ] 内容は具体的か？（問題→解決策の形式）

---

## 注意事項

- **登録に時間がかかる場合がある**。バッチでまとめて処理してよい
- **却下理由は記録せよ**。同じ知見の再提案を防ぐ
- **重要な知見は家老に強調して報告**。dashboard.md に載せる価値があるか判断材料を提供
