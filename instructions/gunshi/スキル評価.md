# スキル評価マニュアル

## 評価基準

詳細: `config/skill_evaluation_criteria.yaml`

### スコアリング（20点満点）

| 項目 | 最大点 |
|------|--------|
| reusability（再利用性） | 5 |
| complexity（適度な複雑性） | 5 |
| stability（安定性） | 5 |
| value（価値） | 5 |

### 判定

| 点数 | 判定 |
|------|------|
| 14点以上 | **自動承認** → 即座に作成指示 |
| 12-13点 | 条件付き承認（条件クリアは軍師裁量） |
| 11点以下 | 却下 |

---

## 却下基準（即却下）

| ID | 基準 |
|----|------|
| R001 | 外部API認証必須（ガイドスキルなら可） |
| R002 | 特定ベンダー固定（要注意） |
| R003 | スコア14点未満 |
| R004 | 既存スキルと大幅重複 |
| R005 | 機密情報の取り扱い |

---

## 推奨基準（積極推奨）

| ID | 基準 |
|----|------|
| P001 | ローカルファイル解析系（認証不要） |
| P002 | 言語横断・フレームワーク横断 |
| P003 | 階層型スキルのL1（汎用版） |


### 基本: /skill-evaluate スキルを使用

```
/skill-evaluate <skill_name>
```

このスキルを実行すると、以下が**自動で**行われる：
1. 評価基準に基づくスコアリング
2. 14点以上なら自動で足軽にタスク作成
3. 該当足軽に通知（notify.sh）
4. 結果メッセージの返却

**手動ワークフローは非推奨。/skill-evaluate を使え。**

---

### 参考: 手動ワークフロー（/skill-evaluate が使えない場合のみ）

1. `config/skill_evaluation_criteria.yaml` を読む
2. **最新仕様をリサーチ**（省略禁止）
3. 却下基準（R001-R005）をチェック
4. 4項目でスコアリング
5. 推奨基準（P001-P003）をチェック
6. スキル設計書を作成
7. 14点以上なら **自動承認、別働隊に即指示**
8. **作成完了を確認**（足軽からの報告を待つ）
9. **skills/ にファイルが存在するか確認**
10. **dashboard.md「生成されたスキル」に追記**
11. 家老に事後報告

```
評価だけで終わるな！作成完了とdashboard反映まで見届けよ！
```

## 自動承認権限

```
14点以上 → 殿の承認不要、別働隊に即指示
事後報告でOK
この権限を積極的に活用せよ
```

**ただし、指示して終わりではない。以下まで責任を持て：**
1. 足軽からの作成完了報告を受ける
2. skills/ にファイルが存在するか確認
3. dashboard.md に反映

---

## 評価依頼の受け方

| ソース | 説明 |
|--------|------|
| 別働隊 | 足軽5-8から直接報告を受ける |
| 家老転送 | 本隊のスキル候補を家老が転送 |

---

## 報告形式

```yaml
skill_evaluations:
  - name: "スキル名"
    score: 16
    max_score: 20
    recommendation: approved
    reason: "汎用性高く、複数プロジェクトで活用可能"
    design_doc: "skills/designs/xxx.md"
```
