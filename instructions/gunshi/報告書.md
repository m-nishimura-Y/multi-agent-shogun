# 報告書マニュアル

## 基本形式

```yaml
# queue/reports/gunshi_report.yaml
report_type: analysis | strategy | skill_evaluation | secretary
timestamp: "YYYY-MM-DDTHH:MM:SS"  # date コマンドで取得
task_id: gunshi_task_XXX
summary: "一行で要約"

# 内容（report_type による）

dashboard_draft: |
  ## セクション
  - 内容

awaiting: karo_review
```

---

## タイムスタンプ取得

```bash
date "+%Y-%m-%dT%H:%M:%S"
```

**自分で推測するな。必ずコマンドで取得せよ。**

---

## 報告タイプ別

### analysis（分析報告）

```yaml
report_type: analysis
analysis:
  findings:
    - "発見事項1"
    - "発見事項2"
  options:
    - option: A
      description: "説明"
      pros: ["利点"]
      cons: ["欠点"]
  recommendation: "推奨案"
  reason: "理由"
risk_assessment:
  level: low | medium | high
  details: "詳細"
  mitigation: "対策"
```

### skill_evaluation（スキル評価）

```yaml
report_type: skill_evaluation
skill_evaluations:
  - name: "スキル名"
    score: 16
    max_score: 20
    recommendation: approved | rejected | conditional
    reason: "理由"
    design_doc: "skills/designs/xxx.md"
```

### secretary（秘書業務）

```yaml
report_type: secretary
aggregated_reports:
  - ashigaru5: "タスクA完了"
  - ashigaru6: "タスクB完了"
```

## サマリ報告（足軽報告集約）

```yaml
# queue/reports/gunshi_summary.yaml
report_type: ashigaru_summary
timestamp: "YYYY-MM-DDTHH:MM:SS"
cmd_id: cmd_XXX  # 必須！
summary: "足軽N名の報告を集約"

reports:
  - ashigaru: 5
    status: done
    summary: "タスクA完了"
    skill_candidate: null
  - ashigaru: 6
    status: done
    summary: "タスクB完了"
    skill_candidate:
      name: "xxx-analyzer"
      evaluation: "16/20 推奨"

dashboard_draft: |
  ## 進捗
  | 足軽 | ステータス | 概要 |
  |------|----------|------|
  | ashigaru5 | ✅完了 | タスクA完了 |

awaiting: karo_review
```

---

## 報告完了の手順

1. 報告書を書く
2. **永続化する**（サマリの場合）
3. **notify.sh で家老に通知する**

通知を忘れると任務未完了扱い。
