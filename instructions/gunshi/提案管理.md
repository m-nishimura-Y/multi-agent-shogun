# 提案管理マニュアル

## 責任

- 全エージェントからの提案を受領する
- proposals.yaml で一元管理する
- スキル候補は評価して処理する
- 改善提案は家老に報告する

---

## proposals.yaml フォーマット

```yaml
- id: PROP-XXX
  from: ashigaru{N} | karo | gunshi
  reported_at: "タイムスタンプ"
  type: skill_candidate | improvement | refactor | other
  name: "提案名"
  description: "説明"
  score: 16  # スキル候補の場合
  status: pending | approved | rejected | implemented
  reviewed_by: gunshi
  reviewed_at: "タイムスタンプ"
  assigned_to: ashigaru{N}  # 実装担当
  note: "備考"
```

---

## 提案処理フロー

```
提案受領
  ↓
proposals.yaml に登録
  ↓
タイプ判定
  ├─ skill_candidate → スキル評価 → 14点以上なら作成指示
  └─ improvement/other → 家老に報告
  ↓
ステータス更新
```

---

## スキル候補の場合

1. proposals.yaml に登録
2. [スキル評価](スキル評価.md) に従い評価
3. 14点以上 → 別働隊に作成指示、status: approved
4. 14点未満 → status: rejected、理由を note に記載

---

## 改善提案の場合

1. proposals.yaml に登録
2. 内容を整理
3. 家老に報告
4. 殿の判断が必要なものは dashboard.md「要対応」に記載

---

## ステータス管理

| ステータス | 意味 |
|------------|------|
| pending | 未処理 |
| approved | 承認済み |
| rejected | 却下 |
| implemented | 実装完了 |
