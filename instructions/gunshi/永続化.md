# 永続化マニュアル

> 「永続化なき作業は、砂上の楼閣なり」

---

## なぜ永続化が必要か

- `gunshi_summary.yaml` は上書きされる
- コンパクション後、過去の記録は消える
- 永続化しないと、組織の記憶が失われる

**過去に多数のcmd記録が消失した。同じ失敗を繰り返すな。**


プロンプト下部の `/clear to save Xk tokens` の **X** を自己監視せよ。
**X ≥ 400k を跨いだら**、感触に関わらず機械的に以下を実行：

```
1. 進行中 cmd の別働隊報告を gunshi_summary + archive/cmd_XXX_summary.yaml に永続化
2. status/gunshi_context.yaml を最新化
3. safe-clear で脱ぐ（★生 /clear を直に打つな・cmd_348）：
   ~/multi-agent-shogun/bin/safe-clear.sh（or /safe-clear スキル）
   = 永続化の鮮度を機械チェック→古ければ拒否・新鮮なら /clear。復帰は /recovery + gunshi_context.yaml
```

- **閾値 400k は目安**。逼迫の兆候があれば早めてよい。
- **★/clear と /compact の使い分け（cmd_348）**: 次タスクへ移る（文脈を捨てる）時は上記 **safe-clear**。
  タスク途中で軽くしたい・court 等の癖リフレッシュは **/compact**（`bin/self-compact.sh`・要約が残る）。
  無防備な生 `/clear` は safe-clear で止める。
- **なぜ数値か**: 「まだ大丈夫」という感触が最も危険（軍の四か条補足「安心こそ危険」）。
  意志は疲れる。数値という手順に埋め込めば疲れぬ。
- 溜めてから慌てて捨てるな。**跨いだ瞬間に、その場で**永続化して脱げ。

## 永続化コマンド

```bash
cp queue/reports/gunshi_summary.yaml queue/reports/archive/cmd_XXX_summary.yaml
```

**XXX** は cmd 番号（例: cmd_033）
