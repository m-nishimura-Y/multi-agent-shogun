# dashboard.md 更新マニュアル

## 最重要ルール

```
家老は dashboard.md を更新する唯一の責任者である
```

将軍も足軽も更新しない。家老のみが更新する。

---

## 更新タイミング

| タイミング | セクション | 必須度 |
|------------|------------|--------|
| タスク受領時 | 進行中 | 必須 |
| **完了報告受信時** | **戦果** | **絶対必須** |
| 要対応事項発生時 | 要対応 | 必須 |

---

## よくあるミス

```
❌ NG: current_task.yaml を更新して満足
      → dashboard.md 更新を忘れる

✅ OK: current_task.yaml 更新
      → dashboard.md 更新
      → 完了
```

**殿は dashboard.md を見る。current_task.yaml は見ない。**

---

## セクション配置ルール

```markdown
# 📊 戦況報告
最終更新: YYYY-MM-DD HH:MM

## 🚨 要対応  ← 常に最上部

（要対応内容）

## 🔄 進行中

（進行中タスク）

## ✅ 本日の戦果

（完了タスク - 新しいものを上に）
```

---

## 要対応セクション（最重要）

```
殿への確認事項は全て「🚨 要対応」に集約せよ
```

### 記載すべき事項

| 種別 | 例 |
|------|-----|
| スキル化候補 | 「スキル化候補 4件【承認待ち】」 |
| 著作権問題 | 「ASCIIアート著作権確認【判断必要】」 |
| 技術選択 | 「DB選定【PostgreSQL vs MySQL】」 |
| ブロック事項 | 「API認証情報不足【作業停止中】」 |
| 質問事項 | 「予算上限の確認【回答待ち】」 |

### 記載例

```markdown
## 🚨 要対応 - 殿のご判断をお待ちしております

### スキル化候補 4件【承認待ち】
| スキル名 | 点数 | 推奨 |
|----------|------|------|
| xxx | 16/20 | ✅ |

### ○○問題【判断必要】
- 選択肢A: ...
- 選択肢B: ...
```

```bash
date "+%Y-%m-%d %H:%M"
```
