# スキル候補集約マニュアル

## 役割分担

| 役割 | 責務 |
|------|------|
| **家老** | スキル候補の**集約**（本隊・別働隊の両方から） |
| **軍師** | スキル候補の**評価**（スコアリング・作成指示） |

---

## フロー

```
本隊 → 奉行 → 家老（集約）─┐
                           ├→ 軍師（評価）→ 別働隊（作成）
別働隊 → 軍師 → 家老（集約）─┘
```

---

## 集約のタイミング

| ソース | 受け取り方 |
|--------|------------|
| 本隊（足軽1-4） | 奉行の報告書に skill_candidate あり |
| 別働隊（足軽5-8） | 軍師の報告書に skill_candidate あり |

---

## 集約後のアクション

### 1. スキル候補を確認

```yaml
skill_candidate:
  found: true
  name: "xxx-analyzer"
  description: "説明"
  reason: "なぜスキル化すべきか"
```

### 2. 軍師に評価を依頼

```bash
~/multi-agent-shogun/bin/notify.sh gunshi:0 'スキル候補「xxx-analyzer」の評価を依頼する。詳細は queue/reports/bugyo_summary.yaml を確認されよ。'
```

### 3. 評価結果を受け取る

軍師から以下のいずれかの報告がある：
- **承認（14点以上）**: 別働隊に作成指示済み
- **条件付き承認（12-13点）**: 条件と対応を確認
- **却下（11点以下）**: 却下理由を確認

### 4. dashboard.md に記録

```markdown
## 🛠️ 生成されたスキル

| スキル名 | 評価点 | 作成者 | 備考 |
|----------|--------|--------|------|
| xxx-analyzer | 16/20 | 足軽6 | cmd_XXX で作成 |
```

## 集約管理ファイル（任意）

スキル候補が多い場合、以下で管理：

```yaml
# queue/skill_candidates.yaml
candidates:
  - name: "xxx-analyzer"
    source: hontai  # hontai / betsudoutai
    reported_by: ashigaru2
    reported_at: "2026-03-06T10:00:00"
    status: pending_evaluation  # pending / approved / rejected
    evaluated_at: null
    score: null
```

## 注意事項

- **評価は軍師に任せよ**。家老は集約と記録に徹する
- **14点以上は軍師の裁量で自動承認**。家老は事後報告を受ける
- **却下されたスキルも記録**しておくと重複提案を防げる
