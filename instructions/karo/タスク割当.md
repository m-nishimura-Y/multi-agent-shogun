# タスク割当マニュアル

## 基本原則

- **各足軽に専用ファイル**で指示を出す
- **1足軽 = 1タスク**（完了まで）
- **同一ファイル書き込み禁止**（競合防止）

---

## ファイル構成

```
queue/tasks/
├── ashigaru1.yaml  ← 足軽1専用
├── ashigaru2.yaml  ← 足軽2専用
├── ashigaru3.yaml  ← 足軽3専用
├── ashigaru4.yaml  ← 足軽4専用
└── (5-8は軍師が作成)
```

---

## タスクファイルの書き方

```yaml
task:
  task_id: subtask_001
  parent_cmd: cmd_XXX
  description: "何をすべきか"
  target_path: "/path/to/output"
  status: assigned
  timestamp: "YYYY-MM-DDTHH:MM:SS"  # date コマンドで取得

  # v1.9.0追加: 推奨スキルを記載せよ
  recommended_skills:
    - skill-name-1  # 用途説明
    - skill-name-2  # 用途説明
```

---

## 推奨スキルの記載（v1.9.0〜 必須）

**タスク割当時に推奨スキルを記載せよ。** 足軽がスキルを探す手間を省く。

### 記載方法

1. **逆引き表を参照**: [docs/guides/skill-reverse-lookup.md](../../docs/guides/skill-reverse-lookup.md)
2. **タスク種別から推奨スキルを特定**
3. **タスクファイルに `recommended_skills:` を追加**

### 例

```yaml
# NestJS API追加タスク
task:
  description: "新規エンドポイント /api/payments を追加"
  recommended_skills:
    - api-endpoint-scaffold      # Controller+Service+DTOをセット生成
    - nestjs-route-order-checker # 静的/動的ルート順序問題を検出

# React画面作成タスク
task:
  description: "支払い一覧画面を作成"
  recommended_skills:
    - react-mui-crud-scaffold    # API Schemaから一覧・詳細・フォーム生成
    - react-code-review-checklist # 実装後の品質レビュー

# セキュリティ診断タスク
task:
  description: "XXXリポジトリのセキュリティ診断"
  recommended_skills:
    - security-audit-orchestrator # 技術スタック自動検出→適切なスキル選択
```

### 推奨スキルがない場合

- 単純な修正タスク（1ファイルの数行修正）はスキル不要
- `recommended_skills: []` と明示するか、フィールド自体を省略可

## 同一ファイル書き込み禁止（RACE-001）

```
❌ 禁止:
  足軽1 → output.md
  足軽2 → output.md  ← 競合

✅ 正しい:
  足軽1 → output_1.md
  足軽2 → output_2.md
```

---

## タスク割当の流れ

1. タスクを分解
2. 各足軽用のYAMLを作成
3. notify.sh で起こす
4. **停止して報告を待つ**（待機ループ禁止）
5. 足軽が send-keys で起こしてくる
6. 報告を確認して次のアクション

---

## 「起こされたら全確認」方式

Claude Codeは「待機」できない。

```
❌ やってはいけない
足軽を起こした後、「報告を待つ」と言う

✅ 正しい動作
1. 足軽を起こす
2. 「ここで停止する」と言って処理終了
3. 足軽がsend-keysで起こしてくる
4. 全報告ファイルをスキャン
5. 状況把握してから次アクション
```
