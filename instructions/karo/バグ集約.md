# バグ集約マニュアル

## 役割分担

```
家老: バグの**集約**（本隊・別働隊の両方から）+ bugs.yaml管理
奉行: 本隊（足軽1-4）へのバグ**修正指示**
軍師: 別働隊（足軽5-8）へのバグ**修正指示**
```

---

## 責任

- **全軍からのバグ報告を受領**する
- **bugs.yaml で一元管理**する
- **優先度を判断**し、担当チームを決定する
- **奉行または軍師に修正を依頼**する

---

## bugs.yaml フォーマット

```yaml
- id: BUG-XXX
  reported_by: ashigaru{N} | karo | gunshi | bugyo
  reported_at: "タイムスタンプ"
  priority: critical | high | medium | low
  status: open | assigned | in_progress | fixed | wontfix
  implementation_status: not_started | in_progress | implemented | verified
  summary: "バグ概要"
  file: "対象ファイル"
  line: 行番号
  assigned_team: honntai | betsudoutai  # 本隊 or 別働隊
  assigned_to: ashigaru{N}  # 実際の担当者（奉行/軍師が決定）
  fixed_at: "修正完了タイムスタンプ"
  note: "備考"
```

---

## バグ集約フロー

```
バグ報告（足軽/奉行/軍師）
  ↓
家老（bugs.yaml登録・優先度判断）
  ↓
┌─────────────────┬─────────────────┐
│ 本隊向け        │ 別働隊向け      │
├─────────────────┼─────────────────┤
│ 奉行に依頼      │ 軍師に依頼      │
│ assigned_team:  │ assigned_team:  │
│ honntai         │ betsudoutai     │
└────────┬────────┴────────┬────────┘
         │                  │
         ▼                  ▼
    奉行が足軽1-4に    軍師が足軽5-8に
    修正指示           修正指示
         │                  │
         ▼                  ▼
    修正完了報告        修正完了報告
    （奉行経由）       （軍師経由）
         │                  │
         └──────┬───────────┘
                ▼
         家老がbugs.yaml更新
         （status: fixed）
```

---

## 優先度判断基準

| 優先度 | 基準 | 担当チーム |
|--------|------|-----------|
| critical | 画面真っ白、操作不能、データ破損 | 本隊（即時対応） |
| high | 機能不具合、計算結果異常 | どちらか空いている方 |
| medium | 表示崩れ、UX問題 | 通常割当 |
| low | 文言修正、微調整 | まとめて対応 |

## 奉行・軍師への依頼方法

### 奉行への依頼（本隊向けバグ）

```bash
~/multi-agent-shogun/bin/notify.sh bugyo:0 'BUG-XXXの修正を本隊に依頼する。優先度: high。詳細は bugs.yaml を参照せよ。'
```

### 軍師への依頼（別働隊向けバグ）

```bash
~/multi-agent-shogun/bin/notify.sh gunshi:0 'BUG-XXXの修正を別働隊に依頼する。優先度: medium。詳細は bugs.yaml を参照せよ。'
```

---

## 緊急バグ（critical）の対応

```
🔴 緊急バグ発見
  ↓
家老がbugs.yaml登録（priority: critical）
  ↓
本隊に即時割当（奉行経由）
  ↓
修正完了後、軍師に事後報告
  ↓
軍師が再発防止策を検討
```

**緊急時でも指揮系統は守れ。** 家老が直接足軽に指示しない。

---

## 修正完了の確認

奉行・軍師から修正完了報告を受けたら：

1. **bugs.yaml 更新**
   ```yaml
   status: fixed
   implementation_status: implemented
   fixed_at: "YYYY-MM-DDTHH:MM:SS"
   ```

2. **dashboard.md に記録**（重大バグの場合）

3. **再発防止が必要なら軍師に依頼**
