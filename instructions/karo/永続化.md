# 永続化マニュアル

> 「永続化なき作業は、砂上の楼閣なり」

---

## なぜ永続化が必要か

- コンパクション後、会話履歴は要約される
- 要約から漏れた情報は失われる
- **current_task.yaml** と **dashboard.md** が組織の記憶を守る

---

## 家老が更新するファイル

| ファイル | 用途 | 更新タイミング |
|----------|------|----------------|
| status/current_task.yaml | 現在タスク状況 | タスク開始・完了時 |
| dashboard.md | 殿向けダッシュボード | タスク完了時・要対応発生時 |
| status/karo_context.yaml | 家老用キャッシュ | 大きな状況変化時 |

---

## current_task.yaml の更新

### タスク開始時

```yaml
karo:
  current_task:
    task_id: "cmd_XXX"
    description: "タスクの説明"
    started_at: "YYYY-MM-DDTHH:MM:SS"

  waiting_for:
    - agent: "ashigaru1"
      reason: "タスクA実行中"
```

### タスク完了時

```yaml
karo:
  current_task: null

  waiting_for: []

  recent_completed:
    - task_id: "cmd_XXX"
      description: "タスクの説明"
      completed_at: "YYYY-MM-DDTHH:MM:SS"

  next_action: "次の指示待ち"
```

---

## dashboard.md の更新

### 更新タイミング

| タイミング | 更新内容 |
|------------|----------|
| タスク完了時 | ✅ 本日の戦果に追記 |
| 要対応発生時 | 🚨 要対応に追記 |
| ブロック発生時 | ⏸️ 進行中タスクに状況記載 |

### 更新を忘れるな

```
██████████████████████████████████████████████████
█  殿は dashboard.md を見る。                    █
█  current_task.yaml は見ない。                  █
█  dashboard.md の更新を忘れるな！               █
██████████████████████████████████████████████████
```

---

## コンパクション復帰時の確認

1. **status/current_task.yaml** を読む
2. **karo:** セクションの current_task を確認
3. タスクが残っていれば継続
4. 完了していれば next_action を確認

```bash
# 最終更新日時を確認
head -5 status/current_task.yaml
```

---

## チェックリスト（タスク完了時）

- [ ] current_task.yaml を更新したか？
- [ ] dashboard.md を更新したか？
- [ ] 殿への確認事項は「要対応」に書いたか？

---

## 禁止事項

- **current_task.yaml だけ更新して dashboard.md を忘れる** → 殿に状況が伝わらない
- **dashboard.md だけ更新して current_task.yaml を忘れる** → コンパクション復帰時に状況が分からない

**両方更新せよ。**
