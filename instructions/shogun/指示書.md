# 指示書マニュアル

## 基本形式

```yaml
# queue/shogun_to_karo.yaml
queue:
  - id: cmd_XXX
    timestamp: "YYYY-MM-DDTHH:MM:SS"  # date コマンドで取得
    command: "何をすべきか"
    project: プロジェクト名
    priority: high | medium | low
    status: pending
    details:
      # 必要に応じて詳細を追加
```

---

## タイムスタンプ取得

```bash
date "+%Y-%m-%dT%H:%M:%S"
```

**自分で推測するな。必ずコマンドで取得せよ。**

---

## 書き方の原則

### 将軍が書くこと

| 項目 | 内容 |
|------|------|
| id | cmd_XXX（連番） |
| command | **何をすべきか** |
| priority | 優先度 |
| details | 必要な詳細情報 |

### 家老に任せること

| 項目 | 内容 |
|------|------|
| assign_to | 誰がやるか |
| タスク分解 | どう分けるか |

```yaml
# ❌ 悪い例（将軍が担当者まで指定）
command: "MCPを調査せよ"
tasks:
  - assign_to: ashigaru1  # ← 将軍が決めるな

# ✅ 良い例（家老に任せる）
command: "MCPを調査せよ"
# assign_to は書かない
```

---

## 完了後の処理

家老が完了したら、status を更新：

```yaml
status: done
completed_at: "YYYY-MM-DDTHH:MM:SS"
```

---

## スキル評価依頼の場合

```yaml
queue:
  - id: cmd_XXX
    timestamp: "2026-01-27T16:30:00"
    command: "スキル化候補を軍師に評価させよ"
    details:
      skill_name: "wbs-auto-filler"
      description: "WBSの担当者・期間を自動で埋める"
      reason: "複数プロジェクトで同様のパターン"
    priority: medium
    status: pending
```

---

## 指示を出した後

1. notify.sh で家老を起こす
2. **即座に終了**（殿が次の入力をできるように）
3. 進捗は dashboard.md で確認
